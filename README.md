## 🤖 Multi-Agent Architecture

The system uses 8 specialized rule-based agents working together to evaluate equities listed in `symbols.json`. Every number and verdict is computed by explicit, testable rules; nothing is generated by a language model:

1. **Supervisor / Orchestrator Agent**: Manages execution flow, checks incremental SQLite cache (`storage/cache.db`), and orchestrates agent runs.
2. **Historical Data RAG Agent**: Evaluates corporate-action adjusted price history, volume surges, and long-term momentum trends.
3. **Technical Analysis Agent**: Computes SMA 20/50/200, RSI, MACD, Bollinger Bands, and Support/Resistance pivot levels.
4. **Real-Time News & Sentiment Agent**: Fetches online news via free RSS and scores headlines with a keyword sentiment model.
5. **Global Macro & Market Agent**: Turns daily moves in S&P 500, Nasdaq, Brent, DXY, USD/INR and US 10Y into a Bullish/Neutral/Bearish backdrop for Indian equities (weights in `tools/macro_tools.py`).
6. **Fundamental Analyst Agent**: Evaluates financial health (P/E, P/B, ROE, Debt/Equity, Revenue Growth).
7. **Risk & Volatility Agent**: Computes Beta, 95% VaR, Maximum Drawdown, stop-loss placement, and risk-reward ratio.
8. **Master Prediction Synthesizer Agent**: Combines patterns, trend, momentum, news, macro, fundamentals and 30-day history into one weighted evidence score (weights in `agents/synthesizer_agent.py`), then outputs the verdict, entry range, target, stop loss and report. Inputs that are unavailable are excluded and reported as lower data coverage; nothing is invented. Confidence reflects signal agreement and data coverage, **not** a calibrated probability.

## 🛠️ Setup & Installation (Valkey Docker, Backend & Frontend)

### 1. Start Valkey Queue Server via Docker (Recommended)
The background analysis queue ([`storage/queue_manager.py`](file:///c:/Users/tdewa/Documents/LearnPython/stox-main/storage/queue_manager.py)) connects to **Valkey** on `localhost:6379` by default (configurable via `VALKEY_HOST` and `VALKEY_PORT` environment variables), and automatically falls back to SQLite (`storage/cache.db`) if Valkey is offline.

Run the following command to create and start a persistent **Valkey** Docker container:

```powershell
docker run -d --name stox-valkey --restart unless-stopped -p 127.0.0.1:6379:6379 -v stox-valkey-data:/data valkey/valkey:8-alpine valkey-server --appendonly yes
```

**Useful Docker management commands:**
```powershell
# Verify Valkey container is running and responding
docker exec -it stox-valkey valkey-cli ping

# Stop / start existing container
docker stop stox-valkey
docker start stox-valkey

# View Valkey logs
docker logs -f stox-valkey
```

### 2. Start the Backend API Server (`http://127.0.0.1:8765`)
```powershell
# Start or restart the backend HTTP server
powershell -ExecutionPolicy Bypass -File .\cleanup_server.ps1 -Restart

# Or run directly using the virtual environment
.\.venv\Scripts\python.exe dashboard_server.py --no-browser
```

### 3. Start the Angular Frontend (`http://localhost:4200`)
```powershell
cd frontend
npm install
npm start
```

## 📡 Live prices, scheduler & accuracy tracking

**Near-real-time quotes (not tick-by-tick).** While the NSE session is open (09:15-15:30 IST, Mon-Fri) the dashboard
polls one batched quote request every 5 minutes (`QUOTE_POLL_SECONDS`), stores it in `storage/cache.db`, and the page
updates prices in place every 15 seconds. Each price shows its source and time (`● live 14:35`, `⚠ stale`, or
`close 2026-11-06`), and a card warns when the price has moved >2% since its entry/target/stop were computed.

| Source | Setup | Notes |
|---|---|---|
| **Yahoo (default)** | none | Yahoo lists NSE (.NS) as real-time. Unofficial endpoint: personal use only, can rate-limit or break; the last quote is then shown as stale. |
| **Zerodha Kite Connect (optional)** | `pip install kiteconnect`, set `KITE_API_KEY` + `KITE_API_SECRET`, run `python tools/kite_probe.py` once a day | Zerodha's free *Personal* plan is documented as orders/portfolio only; quotes/streaming are part of the paid *Connect* plan. The probe tells you whether your plan returns quotes; if not, Yahoo keeps being used. The token can place orders: keep `storage/kite_token.json` private (it is git-ignored). |

`QUOTE_SOURCES=kite,yahoo` (default) sets the order; Yahoo is always the last resort.

**Market calendar.** Weekends are automatic. Add exchange holidays as `YYYY-MM-DD` strings to `data/nse_holidays.json`
(none are guessed). An unlisted holiday is also detected at runtime (no fresh trades) and shown as "market closed".

**Scheduler** (inside the dashboard process; `AUTO_SCHEDULE=0` disables it): pre-market refresh of macro + news from
08:45 IST, and after 16:00 IST a post-close run that downloads the final candles, re-analyses every symbol, scores past
predictions and prunes old agent outputs. Jobs are recorded per session, so a restart never repeats them and a missed
session (PC off) is caught up the next time the dashboard starts. Today's unfinished candle is never stored as a close.

**Accuracy tracking.** Every verdict is logged and later scored against the actual daily candles (target touched,
stop touched, or 15 trading days elapsed; a candle touching both counts as a stop). Open the **🎯 Accuracy** panel. Treat
the numbers as meaningful only after roughly 30 resolved calls per group. Nothing is tuned automatically.

**Dashboard security (local, single user).** The server binds to `127.0.0.1` only (`DASHBOARD_HOST` to change),
rejects foreign `Host` headers, sends no CORS headers, requires a JSON content type + `X-Stox-Request` header on every
POST, validates symbols, serves files only from `static/`, `reports/` and `news_reports/`, and escapes externally
sourced text. Do not expose it to a network without adding authentication. Free exchange data is for personal use; sharing
the dashboard would need a licensed data vendor.

## ⚡ Incremental Data Storage

All parsed metrics, news, macro sentiment, and agent reports are stored incrementally in **`storage/cache.db`** (SQLite). Re-running analysis utilizes cached data when fresh (<12h old). Price history refreshes are incremental (only missing days are downloaded; a full re-download happens only if a split/dividend re-adjustment is detected).
